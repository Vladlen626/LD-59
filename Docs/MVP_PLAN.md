# LD-59 MVP plan

## 1. К чему идем

Делаем маленькую first-person 3D игру про проверку грузовых поездов на станции в сеттинге дикого запада.

Игрок — контроллер на станции. У него есть долг. Чтобы закрыть долг, он должен зарабатывать деньги и не получать штрафы.

Основная идея: поезд — это документ.
Мы не проверяем состояние поезда в целом и не работаем с пассажирами. Мы проверяем один грузовой вагон на контрабанду и принимаем решение: пропустить или отправить назад.

## 2. Жесткие рамки MVP

Это фиксируем и не расширяем в первом рабочем плане:

- только 1 грузовой вагон за поезд;
- NPC внутри игры нет;
- все поезда грузовые;
- проверка идет на контрабанду, а не на общий техосмотр поезда;
- решение у игрока бинарное: пропустить или не пропустить;
- один поезд = один кейс для проверки;
- нарратив нужен только как рамка и мотивация, не как отдельная система.

## 3. Минимальное игровое ядро

Один полный цикл:

1. Игрок вызывает следующий поезд.
2. Поезд с одним грузовым вагоном приезжает на станцию.
3. Игрок смотрит текущий регламент дня.
4. Игрок осматривает вагон и ищет признаки контрабанды.
5. Игрок переводит рычаг: пропустить или отправить назад.
6. Игрок нажимает отправку.
7. Игра фиксирует результат.
8. В конце дня игрок получает отчет по штрафам и зарплате.

## 4. Что именно проверяем

В MVP игрок ищет контрабанду через простые, читаемые признаки.

Базовый вариант:

- запрещенный тип груза по регламенту дня;
- несоответствие между бумагой и тем, что видно в вагоне;
- явный скрытый запрещенный объект внутри вагона;
- специальная метка или маркер, по которому можно понять, что груз нелегальный.

Важно:

- признаки должны быть понятны визуально;
- игрок должен сравнивать 2 источника: регламент/бумагу и сам вагон;
- не должно быть длинного поиска по уровню и большого количества мелких объектов.

## 5. Что не делаем в MVP

Это вне первого плана:

- пассажиры;
- живые NPC;
- несколько вагонов;
- сложная экономика;
- сложный сюжетный выбор;
- procedural generation на старте;
- длинные прогулки по составу;
- полноценный симулятор железной дороги.

## 6. Технический вектор для LD-59

Используем текущий bootstrap проекта и не трогаем foundation без необходимости.

Новая игровая логика живет в `_Project/Code/Gameplay`.

Минимальный набор сущностей:

- `DayRuleSet` — правила дня;
- `TrainScenario` — кейс одного поезда;
- `ManifestData` — бумага/описание груза;
- `InspectionJudge` — проверка правильности решения игрока;
- `StationFlowController` — основной цикл станции;
- `DebtModel` — деньги, штрафы, долг;
- `DaySummary` — результат дня.

## 7. Первый рабочий milestone

Первый milestone считается готовым, когда:

- игрок может ходить по станции;
- можно вызвать поезд;
- приезжает 1 грузовой вагон;
- можно осмотреть вагон;
- можно принять решение пропустить или вернуть;
- игра умеет понять, верное решение или нет;
- в конце дня показывается штраф и остаток долга.

## 8. Определение успеха

Если после первого milestone цикл "вызвал поезд -> проверил -> принял решение -> получил результат" уже работает, значит у проекта есть игровое ядро.

Дальше можно только наращивать контент:

- больше кейсов;
- новые правила дня;
- более интересные способы прятать контрабанду;
- письма, штрафы, сюжетная рамка.

Но ядро не меняем.
